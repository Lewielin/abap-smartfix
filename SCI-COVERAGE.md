# SCI / ATC check coverage

Generated by `tools/sci-coverage.js` from the rules (`sci.classes`) for the 317 Code Inspector classes of one S/4HANA system (33 of them are category nodes).
SmartFix for ABAP only reads the source in VS Code, so checks that need the DDIC, the compiler, the repository or runtime data are out of scope.

✅ Covered 8 · 🔷 Partly covered 24 · ⛔ Not covered: result could not be confirmed 18 · — Out of scope 267

**Annotation names.** Every pseudo comment / pragma below is the one the check's own message uses in the SCI message catalog
of the reference system (`SCIMESSAGES` of the check class); `test/sci.js` checks each rule against that catalog (`src/sci-catalog.js`).
If your system uses other names, set them in `abap-smartfix.tokenOverrides` or run **Learn Annotation Names from Workspace**.
Checks whose annotation name, finding position or limits could not be confirmed are not included (see the ⛔ table).

**With ATC.** The tables below are about the checks SmartFix for ABAP finds in the source itself. When ATC runs in your SAP system,
a finding of any check class, also one marked out of scope here, gets the pseudo comment / pragma its check class and message code
use in the catalog (`src/sci-messages.js`, plus the messages seen in ATC results in `src/sci-catalog.js`); a message that cannot be
suppressed in the code is listed as a manual fix (exemption). Without a check class in the ATC result, a message code that several
check classes use with different annotations is not guessed: it is listed as a manual fix.
